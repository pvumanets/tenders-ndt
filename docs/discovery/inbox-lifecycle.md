## Колонки доски

| Колонка | Кто попадает | Срок подачи |
| --- | --- | --- |
| **Горячие** (L1) | Явные **услуги** НК по правилам тиров | ≥ сегодня (МСК) |
| **Сильные** (L2) | Услуга НК видна, сигнал слабее | ≥ сегодня (МСК) |
| **Смотреть** (L3) | Пограничные; **поставка / калибровка / приборы** — всегда сюда | ≥ сегодня (МСК) |
| **Просроченные** | Были в L1–L3 (или эквивалент), но срок подачи **уже прошёл** | < сегодня (МСК) |

Порядок колонок слева направо: Горячие → Сильные → Смотреть → **Просроченные** (четвёртая **справа**).

- Карточку в «Просроченных» можно **открыть** и посмотреть поля.
- На карточке — бейдж **«Срок подачи вышел»**.
- В Горячих / Сильных / Смотреть просроченных **не держим**.
- Сортировка в «Просроченных»: **свежие протухшие сверху** (недавно ставшие просроченными — выше).

### Скролл доски

Горизонтальный скролл (четыре колонки) — **только внутри блока доски**. Страница / шапка / Tech вокруг **не** уезжают горизонтально вместе с колонками.

Фильтр «только приём заявок, срок с сегодня» на **скрейпе** ([019](../delivery/tasks/019-open-upcoming-only.md)) по-прежнему отсекает прошлое **при сборе с площадки**. Колонка «Просроченные» закрывает дыру: лот уже лежал в БД и **протух после** прогона.

---

## Когда лот становится просроченным

Правило (канон):

1. Берём календарный день **сегодня по Москве**.
2. Если дата срока подачи лота **строго раньше** этого дня → лот обязан оказаться в колонке **Просроченные** (не в Горячих/Сильных/Смотреть).
3. Граница дня: срок **сегодня** (включая до 23:59 МСК) — ещё в живых колонках; срок **вчера** — уже в «Просроченных».
4. Перенос **автоматический**. Механизм P8: **read-time** в Inbox / доске (`deadline < сегодня МСК`). Отдельный суточный crontab не обязателен для показа. Счётчик «Ушли в просроченные» — в задаче [028](../delivery/tasks/028-run-idempotent-report.md). Владелец вручную не гоняет.

Лоты **без даты срока** на доску живых/просроченных **не кладём** в каноне этой поставки; после очистки прода и нового прогона такие строки не ожидаются в нормальном потоке.

## Архив с доски (одно действие)

Из «Просроченных» (и при необходимости с живых колонок в той же модели) директор может **убрать карточку с доски**:

| Поле / действие | Смысл |
| --- | --- |
| `board_hidden` («В архив») | Карточка **исчезает со всех колонок** доски; строка в Postgres **остаётся**; из drawer можно **вернуть** на доску |

Отдельного смысла «скрыть ≠ архив» **нет** — одно действие.

## Повторный прогон (идемпотентность)

Решение владельца (**2026-08-27**, заменяет lock 1В 2026-08-26):

| Ситуация | Действие |
| --- | --- |
| Тот же лот уже в БД, на площадке **ничего не изменилось** | Дубликат **не** создаём; поля **не** трогаем. В отчёте: «**Уже были в системе**». |
| Тот же лот, на площадке **изменились** срок / цена / текст / **документы** | **Обновляем** карточку с площадки. В отчёте: «**Обновлено с площадки**». |
| «Просмотрено», ручной приоритет, статус ИИ-разбора | **Не сбрасываем** при обновлении. |
| Лот **новый** для нас | Обычный ingest + тир по **правилам**; ИИ — **отдельным шагом** (не при ingest). |
| Тот же лот, срок **уже вышел** | Не дублируем; **Просроченные** по правилу даты. |

Итог: повторный Старт **не плодит** копии; **не затирает** triage; **подтягивает** свежие данные с площадки.

## Отчёт после прогона (Tech)

После Старта / очереди поисков в Tech (или в логе прогона) — **полные фразы**, минимум:

| Счётчик (UI) | Смысл |
| --- | --- |
| **Новые лоты** | Впервые попали в нашу БД |
| **Уже были в системе** | Нашлись снова, **без изменений** на площадке |
| **Обновлено с площадки** | Были в БД; срок / цена / текст / документы **изменились** — карточка обновлена |
| **Ушли в просроченные** | **Все** лоты, которых система **впервые** отметила протухшими в окне этого прогона / связанного шага |

Формат UI — в задаче [028](../delivery/tasks/028-run-idempotent-report.md); этот файл задаёт **смысл**, не вёрстку.

Дымовой критерий: повторный Старт того же поиска → «Уже были в системе» **> 0**, «Новые лоты» в основном **0**.

## Связь со скрейпом

```text
Площадка (срок ≥ сегодня) → прогон → ingest (правила → L1/L2/L3)
                              ↓
                    уже есть, без diff → «уже были»
                    уже есть, diff → «обновлено с площадки»
                    новый → на доску; ИИ — отдельным шагом
                              ↓
              read-time: срок < сегодня МСК → «Просроченные»
```

Скрейп **не обязан** заново «переписывать» старые строки только потому, что лот снова попал в выдачу.
