Канон **плюс-фраз** для поиска на площадках. Порядок: **от сложных (точных) к простым**. Лимита 1000 нет.

**Минус-фразы, pipeline и таблицы plus+minus по пакетам A–E** — только в [`search-system-v2.md`](./search-system-v2.md). Этот файл не дублирует минусы.

---

## Принципы

1. **Только открытые лоты** — приём заявок, срок подачи ≥ сегодня (МСК). Прошлое и закрытое не ищем ([019](../delivery/tasks/019-open-upcoming-only.md)).
2. **Без потолка 1000** — на один точный запрос ожидаем **~30–60** строк; страховка (E) может дать больше — это ок.
3. **Несколько именованных поисков** — пакеты **A → B → C → D → E** в очереди.
4. **Lock 034:** в query Rostender **только полные фразы**; единственная аббревиатура — **ВИК**. Усечения и прочие аббревиатуры (НК, УЗК, ПВК) **убраны**. Диагностирование — не query.
5. **Lock v2 (036):** у каждого поиска свой `exclude[]`; минус режет на списке; соц/кровля-минусы — в основном на D, не на A/B ([`search-system-v2.md`](./search-system-v2.md)).
6. **Уровень E (страховка)** — `контроль сварных соединений` + `сварных соединений`; без диагностики.
7. **Стилоскопирование / профильный / радиационный** — **не** отдельные query; только правила оценки.

## Уровни фраз (плюс)

| Уровень | Смысл | Фразы (плюс) |
| --- | --- | --- |
| **A — услуга целиком** | Явная работа НК | неразрушающий контроль · дефектоскопия |
| **B — метод как работа** | Конкретный вид контроля | ультразвуковой контроль · визуально-измерительный контроль · капиллярный контроль · радиографический контроль · гаммаграфический контроль · толщинометрия ультразвуковая |
| **C — аббревиатуры** | Короткие запросы | **ВИК** (единственная аббревиатура) |
| **D — контроли** | Приёмка / стройконтроль | принимающий контроль · приёмочный контроль · входной контроль · **строительный контроль** (не минус; минусы контекста — на пакете D в v2) |
| **E — страховка** | Широко | контроль сварных соединений · сварных соединений |
| *(не query)* | Только правила | стилоскопирование · профильный контроль · радиационный |

## Обработка внутри одного поиска (целевой v2)

```text
queries[] (плюс)
  → union по native id
  → exclude[] (минус) по title — drop до скоринга
  → без обрезки limit_n
  → скоринг → L1 / L2 / L3
  → ingest на доску
  → ИИ — отдельным шагом
```

**Код сейчас (до 036):** плюс-сиды 034/035; минус-фильтра нет; hard L3 стройконтроль — долг к откату.

## Почему убрали лимит 1000

| Было | Стало |
| --- | --- |
| Страх «скачать слишком много» | Фильтр «только открытые с сегодня» уже режет прошлое |
| Первые query съедали лимит | Отдельные поиски A–E; без потолка; мусор D режет минус v2 |
