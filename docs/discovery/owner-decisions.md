| 1 | Колонка «Смотреть» — что там лежит? | Лоты, которые **система сама** оценила слабо (пограничные услуги, поставка приборов, калибровка). **Не** «только то, что я вручную перетащил». | 2026-08-27 |
| 2 | Тот же тендер снова нашёлся на площадке — карточку трогаем? | **Да, обновляем**, если на площадке что-то изменилось: срок, цена, текст, **документы докинули**. «Просмотрено» и ручной приоритет **не сбрасываем**. | 2026-08-27 |
| 3 | Лимит «1000 лотов на поиск» | **Убираем.** Ищем только **будущие открытые** (приём заявок, срок с сегодня). На один запрос ожидаем **30–60 лотов**, не тысячи. | 2026-08-27 |
| 4 | Как искать по ключевым словам? | **Несколько поисков** в очереди. В каждом — **сначала длинные точные фразы, потом короткие** (аббревиатуры). Список фраз — в [`search-keywords.md`](./search-keywords.md). | 2026-08-27 |
| 5 | Когда включать ИИ? | **Отдельный шаг после прогона по правилам.** Раздел «**Разобрано с помощью ИИ**» + возможность фиксировать ошибки ИИ. **Не** автоматически при каждой загрузке лота. | 2026-08-27 |
| 6 | Принимающий / приёмочный / входной / строительный контроль — искать? | **Да, отдельным пакетом** в очереди поиска (уровень D). | 2026-08-27 |
| 7 | Нужна ли «страховка» широкими запросами? | **Да.** Широкие фразы («контроль сварн», «диагностирование» и т.п.) — чтобы не пропустить лоты без слова «неразрушающий». **Мусор разбирает ИИ** (для этого и подключаем). | 2026-08-27 |
| 8 | Усечения со скрина (`дефект.`, `нераз.`, `ультр.`, …)? | **Да**, кладём **вместе** с полными словами в запросы. | 2026-08-27 |
| 9 | Что сносим на проде после выкладки 027–029? | **Всё:** карточки лотов, «просмотрено», ручные приоритеты, файлы документов. Без экспорта triage. Потом полный новый прогон. | 2026-08-27 |
| 10 | Стилоскопирование / профильный / радиационный — в поиск? | **Пока нет** — только в правилах оценки. Можно пересмотреть позже. | 2026-08-27 |

## Что это значит на экране

1. **Три колонки живых лотов:** Горячие, Сильные, **Смотреть** — все три заполняет **система** после прогона. Четвёртая — Просроченные (когда срок вышел).

2. **Прогон** идёт широкой сетью: точные услуги → методы → аббревиатуры → контроли (принимающий / входной / …) → **страховка** (широкие фразы). Лимита 1000 нет. В выдаче будет больше мусора — это **нормально**: сито = правила + **ИИ отдельно**.

3. **Повторный прогон** не плодит дубликаты. Если лот уже был — смотрим, изменилось ли на площадке. Изменилось — **обновляем карточку** (в т.ч. новые файлы). Не изменилось — в отчёте «уже был в системе».

4. **ИИ — по твоей команде:** после прогона лоты лежат с тиром **по правилам**. Когда готов — жмёшь «Разобрать с ИИ». ИИ обязан **хорошо отличать мусор** (обучение, железо, не наше). Результат — в разделе «Разобрано с помощью ИИ»; косяки можно отметить.

5. После выкладки кода 027–029 на прод — **полный снос** старых лотов и состояния, затем чистый прогон.

## Что ещё не в коде (честно)

- Сейчас в программе доска может показывать **не все** «Смотреть» — старый порог «только сильные». Исправим в задачах 027–029.
- Лимит 1000 и один запрос «неразрушающий» — **ещё в коде**. Новые сиды A–E + усечения — **отдельной задачей** после discovery (не в этой docs-поставке).
- API в [`sales-inbox-api.md`](../delivery/sales-inbox-api.md) пока описывает старую модель — **синхронизируем при коде**, не раньше.
