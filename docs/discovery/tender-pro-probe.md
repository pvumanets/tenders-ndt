## Факт / гипотеза / пробел

| Тег | Утверждение |
| --- | --- |
| **fact** | Список: `GET https://www2.tender.pro/api/tenders/list` → HTML 200 (`text/html`). `Accept: application/json` всё равно HTML. `POST` того же URL → **405**. `www.tender.pro` отдаёт ту же форму. |
| **fact** | Поле «Товар в тендере» = query `good_name`. Статус «Открыт» = `tender_state=1`. Страна «Россия» = `country=1`. Тип «Все» = `tender_type=100`. Строк на странице = `by=25`. |
| **fact** | Грид в первом HTML: таблица (`table-stat__row`), колонки id / название / даты / тип; ссылка карточки `/api/tender/{id}/view_public`. httpx+BS4 достаточно. |
| **fact** | Дамп Netscape (`TPROv1` + `_ym_*` + `mdd`) **не показал** кабинет НДТ / «Выход». Виджет логина на странице есть. Поиск списка при этом **публичный** — строки приходят без идентификации компании. |
| **fact** | Хиты 2026-08-13 (открытые, РФ, `good_name`): **ВИК — 2**, **ПВК — 0**, **УЗК — 3**, **РК — 10**. Счётчик в HTML: `(всего строк: N)`. |
| **fact** | Тот же набор в поле `tender_name` (название): ВИК/ПВК/УЗК = 0; РК = 1 ложный хит (госномер «…РК»). Канон владельца «искать по товарам» подтверждён. |
| **fact** | Короткие аббревиатуры дают **шум**, не услуги НК: РК цепляет госномера/файлы (`Х876РК`); УЗК есть в HTML лотов ТМК «Металлические запасы»; ВИК-хиты «Мебель» / «КИП» **не содержат** «ВИК» в публичном HTML карточки. |
| **fact** | Карточка `GET /api/tender/{id}/view_public` 200 без логина. Блоки: «Общая информация», «Документы», «Товары». Часть полей — «Зарегистрироваться, чтобы узнать». Срок: «Прием заявок до: … MSK». |
| **fact** | JSON-RPC 2.0 живой: `POST https://www.tender.pro/api` (также `/api.json`, `www2`), сервер **PGWS v1.11**. `info.tenderlist_by_set` требует `_key` и `set_id` (без ключа — `Y0001`). Параметр `good_name` в echo args **не появляется**. |
| **fact** | Публичный `tender.get_status` с `{id}` отвечает без ключа (пример: id `1227021` → `data: 2`). Методов `good.search` / `tender.search` нет (`-32601`). |
| **hypothesis** | Полная сессия ЛК (свежий экспорт после перелогина) откроет номенклатуру «Товары» и файлы без заглушки «зарегистрироваться». Не проверено этим дампом. |
| **gap** | Пагинация >25; прямые URL скачивания документов; смысл кода `tender.get_status.data`; нужен ли `_key` от техподдержки Tender.Pro, если UI-списка хватит. |

## Стек площадки

```text
cookies.tender-pro.txt (опционально для публичного списка)
  → GET www2.tender.pro/api/tenders/list?good_name=…&tender_state=1&country=1
        → HTML-таблица table-stat__row
  → GET /api/tender/{id}/view_public
        → карточка HTML (документы / товары)

POST www.tender.pro/api   # JSON-RPC 2.0 PGWS; лента по товару без _key недоступна
```

- UI: серверный HTML (design2021), не SPA.
- Хосты: `www2.tender.pro` (форма поиска), `www.tender.pro` (тот же UI + JSON-RPC).
- ИИ / GPT API **не нужны**.

Канонический query списка (имена, не секрет):

`good_name`, `tender_state=1`, `country=1`, `region=0_0`, `tender_type=100`, `tender_show_own=0`, `basis=1`, `tender_promoter=1`, `tender_officer=0`, `by=25`, `order=1`.

Не подмешивать поля виджета логина (`operation=login`, `usetenderlogin`) — они на той же странице.

## Хиты зонда 2026-08-13

Фильтр: `good_name` + открытые + Россия. Примеры — как в гриде, **не** оценка L1–L3.

| Запрос | Строк | Примеры (id — title — приём до) |
| --- | --- | --- |
| ВИК | 2 | `1227021` Мебель — 16.08.2026 18:00; `1229169` Закупка приборов КИП и теплового оборуд-я — 21.08.2026 13:00 |
| ПВК | 0 | — |
| УЗК | 3 | `1199197` / `1199200` / `1199196` Металлические запасы ТМК СТ / СОТ / РАЗ — приём до 01.06.2027 |
| РК | 10 | среди них `1224545` КАМАЗ (в файлах госномер `…РК`); `1223822` запчасти спецтехники; не радиография |

Адаптер NEXT+ должен гонять все четыре запроса (включая пустой ПВК и шумный РК), затем тот же скоринг L1–L3, что rostender.

## Почему не копировать P1 `list_scrape.py`

| | РосТендер (as-is) | Tender.Pro |
| --- | --- | --- |
| Транспорт | httpx GET, HTML сразу | httpx GET, HTML сразу |
| Поиск | `неразрушающий` в названии | **`good_name`** (товар); название даёт почти 0 |
| Разметка | `article.tender-row` | `tr.table-stat__row` + `/api/tender/{id}/view_public` |
| Сессия | Netscape обязателен | список публичный; ЛК — для товаров/файлов |
| Документы | ссылки (P5.5) | имена файлов в карточке; скачивание за логином (gap) |
| Офиц. API | нет в worker | JSON-RPC есть, **не** заменяет поиск по товару без `_key` |

Общий «робот по всем сайтам» не подойдёт: другой query и другие селекторы. httpx копировать можно.

## Рецепт адаптера (когда NEXT+)

Отдельный worker `tender-pro`:

1. Netscape-файл `cookies.tender-pro.txt` (как rostender). После утечки дампа в чат — перелогин и свежий файл.
2. Четыре GET `/api/tenders/list` с `good_name` ∈ {ВИК, ПВК, УЗК, РК}, `tender_state=1`, `country=1`.
3. Парс таблицы → id, title, deadline, url карточки.
4. Карточка `/api/tender/{id}/view_public`; файлы — второй шаг, когда сессия ЛК живая.
5. Ingest в ту же Postgres: `source_platform_id=tender-pro`; скоринг L1–L3 тот же. Короткие аббревиатуры — шум, не повод менять канон запросов.

JSON-RPC `info.tenderlist_by_set` — только если появится `_key` от Tender.Pro; для мониторинга по товару **не** блокирует UI-путь.

Compose bind и код — **вне** этой заметки.
