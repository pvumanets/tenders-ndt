## Зачем

Правила score иногда путают **поставку оборудования** с **услугой НК**. Жёсткие правила ставят тир и **сразу кладут на доску**.

**Страховка поиска** (широкие query уровня E: «контроль сварн», «диагностирование»…) намеренно тянет **больше шума**. Владелец: ИИ подключаем **как раз чтобы классно разбирать мусор** — обучение, железо, нерелевант не должны оставаться в Горячих.

**ИИ** — по **команде оператора** (отдельный шаг), чтобы проверить/поправить и **видеть ошибки**, а не молча перезаписывать всё при прогоне.

---

## Два этапа (не один ingest)

```text
Прогон (правила)
  → tier L1|L2|L3 на доске
  → ai_reviewed = false (или null)

Оператор: «Разобрать с ИИ» (пакет или выбор)
  → provod.ai: title + кусок описания + теги + tier правил
  → JSON: tier + reason_ru
  → ai_reviewed = true; раздел «Разобрано с помощью ИИ»
  → при ошибке: ai_error, tier правил сохраняется, запись в журнал
```

| Этап | Когда | Результат |
| --- | --- | --- |
| **1. Правила** | Каждый прогон | Тир L1/L2/L3 на доске |
| **2. ИИ** | **По команде** после прогона | Подтверждение/правка + `reason_ru`; видимость в отдельном разделе |

Повторный прогон того же лота: **обновление полей с площадки** если изменились (срок, цена, docs) — см. lifecycle. **ИИ не перезапускается** автоматически; `ai_reviewed` сохраняется, пока оператор не запустит заново.

`reason_ru` после ИИ — в drawer «Почему подходит» **всем** операторам.

## UI / продукт

| Элемент | Смысл |
| --- | --- |
| Кнопка «Разобрать с ИИ» | Tech или Inbox; очередь лотов без `ai_reviewed` или выбранных |
| Раздел / фильтр «Разобрано с помощью ИИ» | Лоты с успешным `ai_reviewed` |
| «ИИ ошибся» | Фиксация в журнал (для улучшения промпта/правил); tier можно вернуть к правилам или ручной |
| Баннер при массовом сбое | Если ключ мёртв / обе модели упали — **явно**, не маскировать под «Смотреть» |

## Поля (целевая модель)

| Поле | Назначение |
| --- | --- |
| `ai_reviewed_at` | Когда прошёл ИИ (null = только правила) |
| `ai_tier` | Тир после ИИ (может совпадать с tier правил) |
| `ai_reason_ru` | Краткое объяснение для drawer |
| `ai_error` | Текст сбоя (parse fail, 429, нет ключа) |
| `rules_tier` | Тир до ИИ (для diff «было → стало») |

`manual_tier` из `lot_state` по-прежнему выше движка для UI.

## Провайдер: provod.ai

Публичный API (документация: [provod.ai docs](https://provod.ai/ru/docs), OpenAI- и Anthropic-совместимые контракты):

| Параметр | Значение |
| --- | --- |
| Base URL | `https://api.provod.ai` |
| Предпочтительный контракт для нашего worker | OpenAI-compatible `POST /v1/chat/completions` |
| Запасной контракт (тот же хост) | Anthropic-compatible `POST /v1/messages` (+ заголовок `anthropic-version`) |
| Каталог моделей | `GET /v1/models` (не выдумывать alias) |
| Авторизация | `Authorization: Bearer <ключ>` |
| Переменная окружения | `PROVOD_API_KEY` |

**Секреты:** ключ только в локальном `.env` / на VPS через `--sync`. Никогда в git, md, skills, чат-каноне.

При сбоях alias **не уходим на другой провайдер** — только другая модель на том же `api.provod.ai`.

## Цепочка моделей (один провайдер)

| Порядок | Alias | Роль |
| --- | --- | --- |
| 1 | `claude-sonnet-4-6` | Основная классификация RU-закупок |
| 2 | `openai-gpt-5-4` | Запасная через provod.ai |

1. Один запрос к #1.  
2. Транспорт / 429 / 5xx / плохой JSON → одна попытка #2.  
3. Обе упали / нет ключа → **`ai_error`**, tier **остаётся от правил**, счётчик сбоев в Tech. **Не** silent L3.

## Контракт ответа модели

```json
{
  "tier": "L1",
  "reason_ru": "Кратко почему: услуга проведения НК, не поставка прибора"
}
```

- `tier` ∈ `L1` | `L2` | `L3`
- Промпт повторяет жёсткие правила fit-tiers; **запрет** фильтра по классу опасности
- **Вход:** title, кусок описания, теги score, tier правил, опционально `platform_id`

---

## Что не делает ИИ

- Не ищет на площадках (это прогон httpx)
- Не решает просрочку
- Не создаёт дубликаты
- Не запускается автоматически при ingest (lock 2026-08-27)
- Не ходит в API вне provod.ai
